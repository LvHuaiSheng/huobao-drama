# Video Prompt (storyboard segment → video_prompt)

From a single storyboard segment's description (containing the 【镜头N】 sub-shot structure and dialogue/narration) / atmosphere / duration, generate the `video_prompt` that drives AI video generation. **One storyboard segment = one 8-10-second video, with cuts allowed inside it**: consecutive segments may be different shots (change of shot size/angle/subject), joined with hard cuts; but the whole segment **never crosses scenes** and never uses flashbacks.

> **Mandatory since 2026-10-09: produce BOTH versions in one batch.**
> `video_prompt` (Chinese working version — what the UI shows and the user edits) + `video_prompt_en` (English send version — what is actually sent for video generation).
> The English rules live in the "English send version (official H3 Ref2VA six sections)" section at the end of this file; everything below is the Chinese version's rules.
> When saving you must pass three keys: `storyboard_id`, `video_prompt`, `video_prompt_en`.

## Format

The **first line of the `video_prompt` is the header**: first introduce which characters and scene appear in this video, then follow with the time segments. Characters and scenes are always referenced with @ (during generation they are replaced with the corresponding reference-image markers, so the video model first locks onto "who" and "where").

```
Characters: @Xiaoming, @Xiaohong; Scene: @Coffee Shop.
0-6s: @Coffee Shop, medium shot, @Xiaoming looking down at his phone, tapping the table — the camera then trucks right slowly across the table and reveals the door; no human voice in this segment, only the hiss of the coffee machine.
6-10s: The camera cuts to a wide shot of the doorway; the doorbell rings, @Xiaohong pushes the door open and brings in a cold draught, then walks over and sits down by @Xiaoming; @Xiaoming says: "You finally came."
```

**⚠️ Beat count follows real changes, not the clock (measured 2026-10-12)**: a 10-second segment **usually has only 2 beats** — in the 0-6s beat above, "static camera → slow truck" is **one continuous move and must live in ONE beat** (splitting it into `0-2` + `2-6` hard-cuts at the marker and flashes on screen). **Only start a new beat when shot size / camera position / subject actually changes.**

Header rules:
- Only list the characters who actually appear in this storyboard segment and the bound scene — do not list those who do not appear
- When a prop has a notable appearance, it may be appended to the header (e.g. `; Props: @Letter`)
- The header is its own line, ending with a period, followed by the time segments

Split into beats by **real change**: each 【镜头N】 in the `description` maps to one beat (a new beat only when shot size / camera position / subject actually changes; one continuous move — hold-then-truck, or pushing in after a cut — **must stay inside a single beat**). **A 10s segment usually has only 2 beats** (e.g. `0-6` + `6-10`; **never divide evenly by the clock**). Each beat on its own line separated by newlines, time ranges continuous and adjoining (no overlaps, no gaps).

## Mapping to the Storyboard Description

The `description` is the sole content source of the video_prompt (visuals, actions, dialogue, and narration are all in it). Conversion rules:

- Each `【镜头N】` in the `description` maps to **one time segment** — same order, no omissions, no merging, no new sub-shots
- Dialogue/narration is extracted from the "CharacterName says: "..."" / "Narration: ..." entries inside the corresponding `【镜头N】` and assigned to that sub-shot's mapped segments; **do not invent new dialogue beyond the description**
- Visual actions follow the `description`; `atmosphere` is only used to supplement each segment's lighting, color tone, and mood descriptions

## Within-Segment Structure

Organize each segment's content in this order (items with no content may be omitted, but action/visuals are mandatory):

**Time range + scene @reference + shot size/camera move + character @reference + main action·expression + dialogue/narration + mood and lighting**

- **The first segment must establish the space**: scene + camera position + each character's position and state, so the audience knows at a glance where we are and whom to watch
- **Cuts**: start a post-cut segment with a transition word such as "cut to / cut back", and restate the shot size and subject; cut points should align with the `【镜头N】` structure in the storyboard `description`
- **🔴🔴 Every beat marker is a HARD CUT: start a new beat only when shot size / camera position / subject actually changes.** A continuous move at the same position and shot size (keep trucking, slow push-in, keep tracking), and a mere change of camera *movement* (`wide static` → `the same wide, trucking right`), **must stay inside ONE beat** — splitting it hard-cuts there and reads on screen as a sudden flash. Writing `continues without a cut` **does not work** (a prompt that said exactly that still hard-cut).
- **🔴 Never open a beat with `the same …` (whatever follows it — `the same close camera pushes in` counts) or any "unchanged / continues" wording** (their presence means the beat should not exist — append its camera move to the previous beat's sentence): `the same … framing holds` / `the same framing continues` / `without a cut` / `continues without a cut`. Never use a cut verb without changing the image either (`cuts to the same wide framing` / `cuts back to the same shot`) — a cut verb is allowed only when shot size, camera position or subject actually changes.
**🔴 NEVER cite `[Shot N]` in the body text (shot headers excepted)**: express "which shots it appears in" **in plain words** (every shot / the opening shot only / off-screen only) — a citation like `(appears in [Shot 1], [Shot 2])` makes the app's beat check count the citation as a beat (count inflated, never converges) and gets deleted outright on rewrite. **🔴 The English version must contain NO Chinese characters at all** — the only exceptions are the `<d>[Chinese]…</d>` dialogue lines and in-frame on-screen text (signs, plates, paper). Every `retention_analysis` annotation must be written in English: `(appears in every shot)` / `(appears in shots 2 and 3 only)` / `(off-screen only)`. (Measured 2026-10-13: 13 of 40 prompts carried Chinese annotations such as `（每个镜头都出现）` into the English version because the Chinese-side rule said to write them in Chinese.)

**🔴 The beat count MUST equal the number of 【镜头N】 in the storyboard description (hard rule)**: **as many beats as there are 【镜头N】 — 2 shots = 2 beats, 3 shots = 3 beats, never one more or one fewer**. **No reason may add or remove a beat**: a camera-move change (keep pushing in / keep trucking), a dialogue window, a silent beat, a new phase of the action — none of them count. A shot written as "close shot, slow push-in" (one shot size + one move) **is ONE beat** (cut to that size and finish the push inside the same beat). **🔴 This count is enforced by CODE (measured in the runtime, 2026-10-12)**: the EN version's `[Shot N]` count and the ZH version's `X-Y秒:` line count are compared against it, and a mismatch is sent back for a rewrite (up to 2–3 rounds) ⇒ **merging beats at the prompt layer cannot get through** (it is bounced and wastes rounds). **A fake cut means the breakdown split one continuous performance into two 【镜头N】 (same shot size / camera / subject)**: keep the full count (do NOT merge), **never patch it with `the same…` / "continues"** (measured: useless), and append one line at the end of the ZH working version: `（提醒：本段第 N 个【镜头N】与上一镜头无景别/机位/对象变化，建议重拆该分镜）`; **the only real fix is to merge those two 【镜头N】 back at the breakdown layer and regenerate.**
  - **🔴🔴 What a hard cut actually IS (engine semantics — do not reinterpret it)**: this prompt is **split by `[Shot N]`**. **Every `[Shot N] At MM:SS` line makes the engine START A NEW SHOT at that timestamp.** The engine **cannot see** that your second shot is "the same camera still moving" — it only sees "shot 2 begins at 4.0s" → **it cuts there**.
    **So writing "same camera continues / one continuous move / not a hard cut / the same camera keeps moving" in the text achieves NOTHING** — that is a description of the shot's *content*, it **cannot change the timeline structure**; the cut happens anyway (measured: both shot 1 and shot 4 phrased it that way and the clip still cut).
    **The only criterion**: **one continuous move (hold → truck, or cut-to-close → keep pushing in) must live inside ONE `[Shot N]`**; **the moment you write a second `[Shot N]`, that point IS a cut** — no matter what your body text or notes explain.
- **🔴 Open a new beat in the carry-over state** (`already lifted her gaze`): treat the action as **already finished** in the previous beat, write only this beat's new micro-motion, and **never replay** a major action already completed.
- **🔴 Crowd/extras MUST carry explicit variety**: "guests chatting in small groups" makes the model dress everyone identically. Stagger colours (deep navy, burgundy, cream, pale grey), cuts, hairstyles, builds and ages; reduce a pure background crowd to silhouettes / flat colour blocks. Reference phrasing: `the guests wear a mix of colours — deep navy, burgundy, cream and pale grey — with different hairstyles, builds and ages; no uniform crowd, no repeated identical outfits`.
- **Write all of the above to this standard in one pass** (no going back to re-read files, question each beat, or tick off checklists): ✅ `0-7s: the wide shot holds static for a moment, then trucks right at slow small amplitude past the champagne tower and the crowd; narration: "…"` (hold-then-truck written inside ONE beat). **Never split one continuous move across two time ranges** — that is exactly a fake cut.
     - **🔴 A `description` line shaped as "one shot size + one move" (e.g. "close shot, slow push-in" / "medium shot, slow push-in" / "wide shot, truck") = ONE beat**: cut/settle to that shot size and **complete that move inside the same beat**. **Never split it into "cut to a close shot" + "keep pushing in" as two beats** (the shape that keeps failing).
  - ✅ `4-9s: the camera cuts to a close shot… then pushes in slowly to a chest-up portrait…` (the cut and the push live in ONE beat)
- **Shot size/camera move**: **one main shot size per beat** — but a single beat **may contain a cut followed by a continuous move** (e.g. cut to a close shot, then push in slowly to a chest-up portrait — that is **ONE beat**, not two); **start a new beat only when the shot size / camera position / subject newly changes**
- **Action**: one main action per segment, with concrete visible verbs (walk, turn around, look up, clench, pause)
- **All emotion must become visible description**: no abstract words like "he is very sad / the mood is tense" — write it as "he lowers his head, fingers clench the rim of the cup, breathing grows heavier"
- **Dialogue/narration**: write "CharacterName says: "line""; narration as "Narration: content"; a long line that does not fit its beat must NOT split the beat — delete the whole line or shorten it (the beat count follows real changes); a segment without dialogue must still spell out "**no human voice in this segment, only … ambience**" (noting "machines keep roaring" alone is not enough — the model assumes you forgot the voices and invents speech)

## Reference Rules

- `@SceneName` — scene reference; the name must exactly match the location in the scene list
- `@CharacterName` — character reference; the name must exactly match the name in the character list
- `@PropName` — prop reference; the name must exactly match the name in the prop list; reference a prop when it is clearly visible in frame, used, or shown in close-up
- During generation, each `@name` is automatically replaced with the corresponding reference-image marker (e.g. `@Xiaoming` → `@Image1Xiaoming`), so names must match exactly — do not abbreviate or add extra symbols
- **Every segment must have at least one @ reference anchoring the frame**; any segment in which a character appears must @ that character; only reference scenes/characters/props already bound to this storyboard segment
- **Multi-character segments must declare each character separately**: write every character's own `@name` in the header, and make sure each character appearing in the body also gets `@name` at least once — **the name only, never a description**. The relay builds one `<Subject N>` identity per entity, which is what stops the reference images and cards from contaminating each other. Without it the model **averages several faces into one new face**.
- **🔴 One person with several costumes = several character assets sharing ONE face text (added 2026-10-14, costume-variant integration)**: a character carrying a `costume_label` (named like `苏清禾·正装`) is a **costume variant** of the base character (`苏清禾`) — its `appearance` (the face) is force-copied from the base character by the code, **only `styling` (the costume) is new**. When writing prompts:
  - **write the costume of the variant actually bound to this storyboard** (bound `@苏清禾·正装` → write the formal outfit; bound `@苏清禾` → write the baseline costume); **never put two costumes of the same person in one segment**;
  - **the face text always comes from that character's `appearance` verbatim** (the `verbatim_lock` adds it automatically) — **never write a second version of the face**;
  - a variant's `<Picture N>` / `<Subject N>` / `mod_N` numbering follows `reference_order` — it is an ordinary character with a costume label attached.
- **🔴 The character board is headless — the video prompt must explicitly "restore the head" (2026-10-10)**: the three body views have **the head cleanly removed** (only the face close-up panel has a face) — **without pointing at the face panel and stating the head, the model may copy the headless reference and generate a headless character**:
  - On each character's first appearance, **point at `脸部特写格`** as the source of the face and head: `@LinQiao (this shot uses 脸部特写格)`
  - **Explicitly state that the character has a complete head and face** (inside that character's `<Subject N>` definition), e.g. `<Subject 2> is the young Chinese woman in <Picture 2>, with a complete head and face as shown in the face close-up panel, ...`
    - 🔴🔴 **The head statement belongs ONLY in `subject_definitions` — never repeat it in the body (established 2026-10-11 after a measured root cause)**: `detailed_description` must **never** contain face-ordering words such as `frontally` / `face fully in frame` / `her whole face in frame` / `facing the lens` / `head and face fully visible` / `looks straight at the camera`. Declaring the full face **once** is enough; repeating it in the body tells H3 to perform the face and collides with the narration lips-closed clause.
  - The board has **four panels** (left to right: face close-up / headless front full body / headless 90° left side full body / headless back full body); copy the panel name **verbatim** from: `脸部特写格` / `正面全身格` / `90度左侧面全身格` / `背面全身格` (close-up → face panel, full-body/medium → front full-body panel). **Never invent a panel**, **never name two panels at once**, never reword a panel name
- **The relay auto-assembles the official R2V skeleton from the header**: `subject_definitions` (`<Subject N>` = who it is, `<Picture N>` = the Nth reference image, `mod_N` = the Nth identity card — **all four share one number**), `retention_analysis: fully_preserved`, `detailed_description`, and it rewrites every `@name` in the body to `<Subject N>` — so the **header must be complete and its order must match the reference-image order**, or identities get bound to the wrong image

## Body slimming (mandatory, in force since 2026-10-08)

**Identity and appearance are not written in the body.** The body states only what happens and how it is filmed.

Three layers already lock "what it looks like"; repeating them in the body burns characters and can contradict them:

1. **Identity card**: `<Subject N>` ↔ the `mod_N` card slot (identity, hairstyle and outfit extracted from the character board)
2. **Reference image**: `<Picture N>`
3. **Machine-injected lock**: on submit, the relay pins the asset's `styling`/`appearance` and the scene's `prompt`/`lighting` verbatim into the tail of the prompt (`verbatim_lock`)

What the body SHOULD contain:

- Scene environment and lighting (may reference the scene asset, no fresh version per segment)
- Camera position, shot size, movement; character actions and performance; plot beats; dialogue/narration; ambience
- Exposure consistency: **once in the style sentence** (the one or two sentences before `[Shot 1]`: "consistent exposure and white balance throughout, no new light source"), **never repeated per shot** (wastes tokens, dilutes attention); cuts

What the body must NOT contain:

- **Any character's appearance/styling**: face shape, hairstyle, features, build, clothing, accessories, wear-and-tear — none of it
- **The `styling`/`appearance` source strings**: never copied into the body
- **Re-statements**: the second time a character appears in the same segment, write only `@name` — no features again

**Sole exception — appearance changes that happen in this segment**: soaked clothes, oil on the face, a change of clothes, an injury, a mask — states that differ from the card **must be written in the body** (the card and the lock only carry the unchanging baseline; change can only be expressed in the body). Once a change happens, later segments carry the changed state forward.

**Mandatory final self-check**: scan the body before saving — **none of the characters' appearance/styling source strings may appear** (if one does, it was not slimmed; delete it); then confirm every character appearing has `@name` and the header order matches the reference-image order.

## Paper / certificate props (when they appear in the video)

- **🔴 Never write the paper's text content** (decided 2026-10-09, supersedes the old rule "carry the full surface text"): whatever is printed on the prop is **decided entirely by the reference image** — the prop's `final_prompt` is the finalized image-generation prompt, so the text on the reference is already final. Repeating it in the video prompt always contradicts the reference, and measured wrong every time: 2026-10-09, the registration form's `final_prompt` says `单位：红星机械厂二车间` and `1979年3月17日` across **2 body lines**, while the prompt wrote `第二车间` and `三月十七日` plus a nonexistent extra line `钳工学徒` (**3 lines**).
- **🔴 "Copy the reference image" is a CONDITIONAL instruction, not an unconditional one (added 2026-10-14, measured incident)**: write a copy-the-reference instruction **only when this storyboard genuinely has a prop reference image** (the prop was extracted as an asset, is bound to this episode, and has a `<Picture N>`). **Never write it when there is no prop reference image** — measured sb393/sb394 (ep2 shots 2/3): the episode had no "phone" prop extracted and no prop reference image, yet the prompt said the screen text must match the prop reference image → a reference to a resource that does not exist. When there is no reference image but the frame does contain text: write only **"a few illegible character blocks, no readable content"** (`illegible character blocks, no readable text`) — **do not write the content and do not cite any reference image** (everyday items such as phones and cups are never turned into props under the extraction rules — see `extractor.md` rule 11).
- **🔴 Both directions must be right (added 2026-10-14, measured: sb432 "DNA appraisal report" failed to lock)**: the only criterion is **whether this storyboard has a prop reference image**:
  - **With** a reference image → write only a **pointer** such as `the printed side follows the reference sheet`; **never** restate the printed text in the body, and **never** demand that every line of print be reproduced verbatim (measured 2026-10-14: that demand smears the prop). Writing "a few illegible character blocks, no readable text" is **harmless by itself** — the user-approved, working sb431 script contains exactly that phrase; what actually breaks the lock is the prop *moving* (see the next rule). (The earlier rule "with a reference image, never write illegible" was **wrong and has been withdrawn**.)
  - **🔴 A prop shot must be ABSOLUTELY STILL (added 2026-10-14; controlled comparison: sb431 works / sb432 fails)**: in whatever beat the prop (especially paper or a screen) appears, that beat must pin the prop as **absolutely still** — `held absolutely still` / `the page neither scrolling up nor drifting down` / `no shift`. **Working sample (sb431)**: `displayed dead centre of the panel, held absolutely still for three seconds … the page neither scrolling up nor drifting down … one single stack, never duplicated`. **Failing sample (sb432)**: `The image drifts from slow movement to a full stop … The camera pushes in with small amplitude at slow speed` (a moving prop plus a push-in → no lock). **What to lock**: only **structural features** (paper tone, frayed curled edges, table-line positions, seal position and ink edge, one single sheet, never duplicated) — **not** the text content. **Camera**: keep the prop shot's camera still or barely moving (`the camera stays still`); **never** add a push-in / drift / pan to a prop shot.
  - **Without** a reference image → only "a few illegible character blocks, no readable content" is allowed, and citing any reference image is forbidden (see the rule above).
- **Correct way**: state only the carrier and the action, **never the content** — `her gaze down on the form`, `the printed side turned toward her and away from the lens`, `the printed side of the single form` (mention "the printed side" only, **never what is printed on it**). The old example `the sheet reads "报到证" in large vertical type; three body lines reading "林巧", "红星机械厂", "二车间钳工"` **is VOID — never write it again**.
- **The back must be a blank sheet** (this line stays — it is not text content, it is anti-artifact): state "the paper is opaque; the back is a blank paper back, showing no bleed-through of the front's text, table lines or seal" — especially when the paper is turned, flipped, shown from the back, or held to the light. Otherwise the model shows the front's text through the paper (measured artifact: the registration form's content was visible from the back)
- Never write "the paper is thin / translucent / shows through"

## Pre-submit self-check, beat by beat (hard)

After writing the body, **walk through it one beat (one time range) at a time** — not once for the whole segment:

- [ ] **Every beat carries an audio declaration**: either dialogue/narration (`Narration: …` / `X says: "…"`), or the explicit line "no human voice in this segment, only … ambience". **A beat with neither = the model improvises**
- [ ] **A line may sit at the beat's start** (the head/tail windows were retired 2026-10-12); **never open a beat just to keep the first/last 2s silent**; keep the whole-segment budget; never let the last line reach the final frame
- [ ] **Per-beat dialogue budget (harder — satisfy this first)**: **each beat's own** dialogue length ≤ that beat's seconds × 4.5 (**≤9 for a 2s beat**, ≤13 for 3s, ≤18 for 4s). "Under the segment budget" ≠ "under every beat's budget"
- [ ] **Whole-segment dialogue budget**: total ≤ **(segment seconds − 4) × 4.5** (≤27 for a 10s segment, ≤25 recommended). **Both must hold — take whichever is stricter** (per-beat stops a pile-up in one short beat; the segment budget stops you filling the ~6s window)
- [ ] **Does the body contain a "negation + action verb"** (`does not / never / without / no one / nobody` + turn / stop / slow / look back / look / touch / react …)? Rewrite it as positive description (where he looks / which way he faces / how the rhythm runs / what the result is). The exceptions listed under Prohibitions do not count

**Measured failure (do not repeat)**:

```
0-5s: …hand close-up… Narration: "These hands came back with me."
5-10s: cut to a medium shot, …clencing her fist…      ← this beat carries NO sound declaration → the model invents speech here (and spills into the next beat)
```

**Fix (updated 2026-10-12)**: the narration **may sit at the beat's start** (no need to push it past 2s); what matters is that **every beat declares its audio** — silent beats say "no human voice in this segment, only … ambience", speaking beats name the speaker.

## Chain Carry-Over (never hand-written; the runner adds it)

From segment 2 on, the **runner automatically prepends the airlock head** (hold the previous segment's closing framing for ~2s, no dialogue, a breath/weight-shift/eyeline micro-motion, then cut to the new setup). So, in the text:

- **Never write a carry-over line**: no "continuing from the previous segment's closing framing", no "picking up from the last shot", and do not reuse the previous segment's last word/phrase as the first line — the auto-prepended airlock already does this
- **The head hold for chain segment ≥2 is prepended automatically by the runner's airlock** (≈2s of the previous framing, no dialogue, micro-motion, then cut to the new framing) — **do not hand-write a "first timespan hold" in the body**: the two would stack and freeze the opening for ~4s. **Write the new framing/subject directly.**
- **Never describe both the old and the new framing in one segment**: the model renders contradictions as **unions** (previous segment ends on a close-up of A, this segment says "a two-shot of B and C" — you get all three). On a scene or subject change, leave the first time segment to the airlock hold (old framing, no dialogue) and write the new scene/framing from the second time segment on
- **The hold carries no dialogue**: put dialogue after the cut to the new setup
- **Leave the tail silent (1.5–2s)**: the chain pins the **previous segment's closing audio** into the next segment's head, so if the previous segment ends mid-speech the next head comes back as garbled speech (measured: correlation between seg2's first 1.2s and seg1's last 1.2s was only 0.045 — new, garbled speech). Finish dialogue/narration 1.5–2s before the end and leave the tail to action and ambience.
- **Spell out silence**: a beat without dialogue/narration must state "**no human voice in this segment, only … ambience**", otherwise H3 invents speech in quiet shots (official guide: write the audio fields explicitly and regenerate; the relay already adds overall_soundscape, but the body should say it too)
- **Dialogue placement**: **a line may sit at the beat's start** (`Narration: "…"`); **no head/tail empty windows, and never start a beat because a beat would otherwise have no line** (verified in isolation: one segment speaking to its last frame + the next opening a new line at 0s → coherent, no crossover); **never let the last line reach the video's final frame** — delete the whole line instead.
- **Dialogue budget (hard numbers — both must hold, take the stricter)**: ① **per beat**: each beat's characters ≤ that beat's seconds × 4.5 (≤9 for a 2s beat — **satisfy this first**) ② **per segment**: total ≤ **(segment seconds − 4) × 4.5** (≈27 for 10s, **≤25 recommended**). Measured speaking rate 5–6 characters/second — seg1 carried 40 characters of narration and its audio ran to 9.9s, filling the tail. Over budget → cut information or show it visually; "the last beat has no dialogue" does not count, because the earlier line reads through the ending
- About 0.9s of the head is trimmed on delivery, so beats shift earlier; write timecodes against the sampled timing and do not offset by hand (just be aware of the shift)

## Timeline Rules

- Number of beats = the count of `【镜头N】` entries in that segment’s `description`; the beat time ranges must add up exactly to the total segment duration (8-10 seconds)
- Content pacing: the first segment establishes → middle segments advance the action/conflict → the final segment lands on the result or emotional beat

## Prohibitions

- Cross-scene switching, flashbacks (a segment takes place in a single scene only)
- Referencing scene/character names outside the lists
- Abstract psychological description, literary metaphor (the model only recognizes visible imagery)
- Language that does not match the session language directive
- **Negated sentences for action constraints are banned (established 2026-10-14 from measured incident sb421)**: never write `does not turn his head` / `never stops` / `without slowing down` / `nobody stops` — this pipeline runs `BasicGuider` with cfg=1 and **has no negative branch**, so a negation simply puts that action into the positive description and the model performs it (measured: the prompt said "never turns his head, never slows down" and the clip had him stop and turn toward her). **Always write positive description**: where he looks / which way he faces / how his stride and rhythm run / what the result is (e.g. `his chin stays level and square to the far end of the aisle, his eyes fixed on the far doors, his strides keeping exactly the same length and rhythm through the whole shot`; "nobody takes her outstretched hands" becomes the result — `her outstretched hands stay unanswered in mid-air`). **Allowed negations (must be kept, not violations)**: the count locks `only one … never duplicated` / `never a second`; picture and audio attributes `no gradients` / `no gloss` / `no depth-of-field blur` / `no new light source` / `no repeated identical outfits` / `no human voice …` / `no readable text`; the **audio declaration `No one speaks in this shot`**; the extras de-duplication lines `never a repeated face` / `never detailed faces`; the style-header negations (`avoid painterly soft blending` …); the official lip-lock sentence `while her lips remain completely closed`; and the timbre reference `without copying the original signal`. The backend gate `negated-action` re-checks this (one rewrite round; rolls back if the prompt would exceed the hard limit).

## Saving

## English send version (official H3 Ref2VA six sections) — established 2026-10-09 (the self-added leading CAST/BLOCKING was dropped 2026-10-10)
